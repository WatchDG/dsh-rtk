# dsh-rtk

[![CI](https://github.com/WatchDG/dsh-rtk/actions/workflows/ci.yml/badge.svg)](https://github.com/WatchDG/dsh-rtk/actions/workflows/ci.yml)
[![License: Apache-2.0](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

[English](README.md) | **Русский**

Интеграция [RTK (Rust Token Killer)](https://www.rtk-ai.app/) с
[DeepSeek Harness](https://www.deepseek.com/en/harness/): секция правил в
системном промпте и хук перед выполнением команд, который проводит команды
терминала через RTK. RTK сжимает вывод команд до того, как он попадёт в модель:
обычно на 60–90 % меньше токенов вывода, при этом значимые строки сохраняются.

> **RTK устанавливает сам пользователь — до включения плагина.** Плагин не
> устанавливает, не содержит и не скачивает RTK: он лишь запускает `rtk` из
> `PATH`. Установите RTK с **https://www.rtk-ai.app/** и проверьте
> `rtk --version`. Без RTK плагин загрузится, но хук останется неактивным и
> запишет предупреждение в лог.

## Требования

| Требование | Детали |
|---|---|
| [DeepSeek Harness](https://www.deepseek.com/en/harness/) | 0.2.x (проверено на 0.2.1). Плагин использует сервис `systemPrompt` и событие `tools/pre-execute`. |
| [RTK](https://www.rtk-ai.app/) | Устанавливается пользователем и доступен как `rtk` в `PATH`. Подходит любой актуальный релиз. |

### Сначала установите RTK

```bash
# Windows
winget install rtk-ai.rtk

# macOS / Linux
brew install rtk

# Любая платформа (скрипт установки)
curl -fsSL https://raw.githubusercontent.com/rtk-ai/rtk/refs/heads/master/install.sh | sh
```

Убедитесь, что установлен именно RTK, а не одноимённый пакет:

```bash
rtk --version   # любая актуальная версия
rtk gain        # должна открыться панель экономии
```

Полная инструкция, редакции и удаление:
**https://www.rtk-ai.app/docs/getting-started/installation/**.

## Установка в DeepSeek Harness

Плагин — это бандл профиля DSH, поэтому он действует на все сессии этого
профиля.

1. Откройте страницу **Plugins** в боковой панели DSH (Plugin Manager).
2. Нажмите **Add plugin** / **Install bundle**, выберите этот каталог
   (тот, где лежит `package.json`), и подтвердите.
3. Убедитесь, что **RTK: фильтр вывода команд** включён в списке плагинов.

Тот же шаг доступен агенту через инструмент `plugin_manager` с
`action: install_bundle` и абсолютным путём к каталогу. DSH записывает в
`package.json` профиля зависимость `link:` на каталог; поскольку каталог
связан, после обновления файлов плагина перезапустите DSH, чтобы Host
загрузил новый JavaScript.

Удаление — через Plugin Manager (или `plugin_manager` с
`action: remove_bundle`). Сам RTK при этом не затрагивается.

## Что делает плагин

### 1. Правила в системном промпте

Секция `rtk:rules` вставляется сразу после инструкций shell-инструментов. Она
объясняет модели:

- запускать команды VCS, сборки, тестов, линтеров и пакетных менеджеров через
  `rtk` (`rtk git status`, `rtk cargo test`, `rtk pytest`, `rtk docker ps`, …);
- находить rtk-форму произвольной строки через `rtk rewrite "<команда>"`;
- оставлять файловые операции инструментам харнесса (`read`, `write`, `edit`,
  `glob`, `grep`): они дают номера строк, диффы и проверку «файл прочитан перед
  правкой», которых `rtk read` не даёт;
- считать сжатый вывод полным результатом и восстанавливать выброшенное через
  `rtk recall <hash>`;
- использовать `rtk proxy <cmd>` только когда сжатый результат непригоден, а
  интерактивные команды запускать без rtk;
- запускать `rtk gain` только когда пользователь спрашивает об экономии токенов;
- при отсутствии RTK выполнять команды напрямую и подсказать пользователю
  установить RTK.

### 2. Хук перед выполнением

Плагин слушает `tools/pre-execute` для настроенных shell-инструментов (`pwsh`
и `bash` по умолчанию). Если `rtk rewrite` вернул rtk-форму, вызов
**отклоняется** с точной командой замены:

```
RTK hook: `git status` has an rtk form. Re-run this call with command = `rtk git status`; …
If the rtk form fails, execute the original raw with `rtk proxy git status`.
```

Модель повторяет вызов через rtk. Источник истины — `rtk rewrite`, поэтому
плагин автоматически подхватывает новые фильтры после обновления RTK.

### 3. Страница настроек

**Settings → RTK** состоит из четырёх блоков, данные читает хост (вне
песочницы, поэтому работает, даже когда `rtk gain` падает внутри сессии
агента):

- **Версия** — живой `rtk --version` (`GET /rtk/status`). Если бинарника нет,
  вместо версии секция сообщает об этом и подсказывает, где установить RTK.
- **Экономия токенов** — панель по данным `rtk gain` (`GET /rtk/gain`):
  сводные карточки и разбивки (топ, история, по дням/неделям/месяцам,
  эффективность recall, ошибки парсинга), глобально или по проекту, плюс
  сброс статистики в два клика.
- **Поведение** — настройка ниже, правится на месте без перезапуска.
- **Диагностика** — состояние хука на хосте, счётчики переписываний за
  загрузку, размер кэша и проверка `rtk verify` в один клик
  (`GET /rtk/verify`).

### Почему deny, а не автоперезапись

В контракте DSH аргументы вызова инструмента неизменяемы: обёртки
`tools/execute` могут менять только `exec.signal`, а `tools/pre-execute`
возвращает решение (`allow`/`deny`/`cancel`/`ask`), но не новые аргументы.
Поэтому единственный способ провести команду через rtk — отклонить вызов и
вернуть точную rtk-форму. Это стоит одного дополнительного обращения к модели
на «сырую» команду; при работе по правилам модель сразу пишет `rtk …`.

## Настройка

Все поля необязательны. Переопределите строку `rtk` в патче профиля или
меняйте вживую на странице **Settings → RTK** (сама секция правил
регистрируется один раз при загрузке плагина).

| Поле | Тип | По умолчанию | Значение |
|---|---|---|---|
| `rules` | boolean | `true` | регистрировать секцию правил `rtk:rules` |
| `hook` | `'deny' \| 'off'` | `'deny'` | отклонять сырые команды с rtk-формой или оставить только правила |
| `tools` | string[] | `['pwsh', 'bash']` | какие shell-инструменты слушает хук |
| `exclude` | string[] | `[]` | дополнительные «головы» команд, которые не переписываются (в нижнем регистре) |
| `timeoutMs` | number | `4000` | таймаут одного вызова `rtk`, не больше 60 с |

```yaml
- id: rtk
  config:
    hook: off                  # только правила
    rules: true
    tools: [pwsh, bash]
    exclude: [make, msbuild]   # эти «головы» не переписывать
    timeoutMs: 4000
```

Ответы `rtk rewrite` кэшируются на время жизни плагина (до 512 строк команд).
Укажите `hook: off`, если не нужны отклонения; секция правил при этом остаётся.

## Когда хук не вмешивается

Хук намеренно пропускает вызов, если:

- `rtk` отсутствует в `PATH` (плагин один раз пишет предупреждение, хук
  бездействует);
- у `rtk rewrite` нет фильтра для команды (`Get-ChildItem`, `docker ps` на
  неподдерживаемой версии RTK, …);
- строка содержит синтаксис, который RTK разбирает неверно: кавычки, `|`,
  `>`/`<`, `;`, `` ` ``, `$`, `%`, `!`, скобки, фигурные скобки, `@`, `~` или
  одиночный `&` (цепочка `&&` поддерживается). Например, `git commit -m "fix: x"`
  потерял бы кавычки, поэтому остаётся как есть;
- команда уже начинается с `rtk` в любом сегменте `&&`;
- «голова» команды исключена настройкой;
- вызов отменён (`exec.signal`).

На Windows автоматически исключаются команды, которые RTK реализует через
POSIX-бинарники, отсутствующие в системе: `ls`, `dir`, `tree`, `find`, `cat`,
`head`, `tail`, `grep`, `sed`, `awk`, `which`, `touch`, `chmod`, `chown`, `du`,
`df`. Список можно расширить через `exclude`.

## Проверка

1. `rtk --version` и `rtk gain` работают в терминале.
2. На странице **Plugins** (и в read-only списке **Settings → Plugins**) есть
   **RTK: фильтр вывода команд**, плагин включён.
3. **Settings → RTK** показывает ту же версию, что `rtk --version` в терминале,
   а также панель экономии (сводка и разбивки), форму поведения и диагностику
   с кнопкой `rtk verify`.
4. В новой сессии попросите агента выполнить `git status`: первый вызов `pwsh`
   отклоняется с причиной, содержащей `rtk git status`, а повторный вызов —
   `rtk git status`.
5. `rtk gain` показывает учтённую экономию. Статистика глобальная для RTK, а не
   отдельная для этого плагина.

## Устранение неполадок

| Симптом | Причина / решение |
|---|---|
| В логе ``rtk` executable not found on PATH`` | Установите RTK и откройте новый терминал (или перезапустите DSH), чтобы обновить `PATH`. |
| `rtk` есть, но хук ничего не делает | Хук выключен (`hook: off`), команда исключена или содержит синтаксис, который не переписывается. |
| `rtk --version` работает, но ведёт себя странно | Возможно, установлен другой проект с именем `rtk`; `rtk gain` должен показывать панель экономии. |
| Модель делает лишний вызов | Так и задумано: аргументы в DSH неизменяемы, поэтому сырая команда отклоняется один раз и повторяется через rtk. |
| Команду нужно оставить сырой | Добавьте её «голову» в `exclude` или выключите хук (`hook: off`). |
| rtk-форма не работает | Запустите `rtk proxy <команда>` (сырой запуск, но с учётом) или обновите/исправьте RTK. |

## Разработка

Одна зависимость (`@deepseek-ai/schemastery` для схемы настроек), шага
сборки нет.

```bash
npm ci                   # установить библиотеку схемы настроек
npm test                 # юнит-тесты и проверка манифеста; интеграционные — если установлен rtk
npm run test:unit        # без rtk
npm run test:integration # пропускаются, если rtk нет в PATH
npm run pack:check       # проверить состав npm-пакета
```

Структура:

```
index.js              точка входа Host: экспортирует apply / name / inject / Config
client.js             страница Settings → RTK: версия, экономия, поведение, диагностика (веб-клиент)
lib/config.js         схема Config, значения по умолчанию, нормализация, живой снапшот
lib/command.js        чистый разбор команд и текст отказа
lib/rules.js          текст правил и позиция секции
lib/runner.js         граница execFile для `rtk`: доступность, версия, gain, verify, reset, кэш
lib/plugin.js         подключение к контексту (секция промпта + слушатель pre-execute + роуты /rtk/*)
test/                 наборы node:test (юнит, манифест, интеграция)
```

Если добавляете runtime-модуль, добавьте его в `files` в `package.json`;
иначе тест манифеста упадёт. См. [CONTRIBUTING.md](CONTRIBUTING.md).

## Безопасность и приватность

- Плагин запускает только локально установленный `rtk` и передаёт команду
  одним элементом `argv` в `execFile`, без shell, поэтому текст команды не
  может внедрить синтаксис оболочки на этой границе.
- Плагин не ходит в сеть, не отправляет телеметрию и не хранит историю команд.
  Страница настроек обращается только к собственным аутентифицированным роутам
  хоста `/rtk/*`. RTK — стороннее ПО; его поведение и настройки приватности
  описаны на **https://www.rtk-ai.app/**.
